生成代码执行与工具调用
======================

生成代码在首次调用工具前完成静态验证和执行准备。默认 inprocess 直接
执行预先验证、插入期限检查并编译的 Python 程序。process 后端优先将
数据表达式、条件分支、异常处理和已注册工具调用编译为受限操作计划，
通过固定指令解释执行；其余完整 Python 程序和 NumPy 函数调用进入计算子进程。

这里的环境进程是运行环境模块、管理状态和调用工具的 Python 进程。
如果仿真部署在容器里，计算子进程也在该容器里，两种后端都不创建新容器：

.. code-block:: text

   process:   环境 Python → 传递数据 → 计算 Python 子进程 → 传回结果
   inprocess: 环境 Python → 直接使用已有数据计算 → 得到结果

子进程执行生成的完整 Python 计算代码；其中的环境工具调用交回工具所属
进程执行。工作进程池按需启动和复用，进程数量与 Agent 数量分别管理。

环境工具在所属事件循环运行。只读请求在调用端核验工具的 ``readonly``
元数据；工具名取自已注册接口。仅等待工具返回的操作计划直接使用原事件
循环的并发能力，数值进程池约束计算程序的并发量。

自有容器的性能选择
------------------

``AGENTSOCIETY_CODE_EXEC_BACKEND`` 取 ``inprocess``（默认）或 ``process``。
默认在环境进程内计算，避免频繁传递上下文。该后端将已验证的
Python 程序编译并缓存，在环境所属事件循环直接执行，工具保留原有
Python 参数与返回对象，省去数值子进程、IPC 和数据协议往返。

需要独立终止计算、硬执行期限和工作进程内存上限时，显式开启进程隔离::

    AGENTSOCIETY_CODE_EXEC_BACKEND=process

关闭独立计算进程、恢复默认执行方式::

    AGENTSOCIETY_CODE_EXEC_BACKEND=inprocess

两种后端共用静态许可、导入/属性限制、生成程序的 Python 循环期限检查、
工具注册与只读约束，以及写入后停止整段纠错的规则。进程内路径使用
协作式 Python 期限；NumPy 等原生计算的资源与整场仿真期限由部署环境
管理。``CODE_EXEC_MEMORY_MIB`` 与 ``CODE_EXEC_WORKERS`` 用于 process
后端；JSON 消息与数组传输上限也用于进程边界。进程内执行共享宿主
Python 对象与进程权限，适用于运营者信任的仿真输入和环境工具。

容器应按地图、智能体数量和计算负载配置 CPU、内存上限及作业总期限。
Docker 默认的资源行为见
`资源约束文档 <https://docs.docker.com/engine/containers/resource_constraints/>`_。
后端在执行开始前固定，准备缓存按后端和许可策略区分。

写操作与纠错
------------

工具调用前记录写入尝试。写工具已经开始执行后，程序失败将返回
``status=error`` 和 ``write_attempted=True``，并停止该次 ask 内的整段代码
纠错重试。已经发生的业务写入保留；调用者通过查询工具核对状态后决定
后续操作。工具执行前的语法、策略错误，以及只调用读工具时的执行错误，
继续使用配置的纠错次数。

此行为覆盖工具先修改状态再抛出异常、后续 Python 表达式失败，以及结果
或上下文无法传输等路径。事务、补偿和跨请求幂等键由业务工具实现。

期限与内存
----------

数值工作进程使用 Linux 资源限制：地址空间上限包含 Python、NumPy、
程序数据与代码缓存；核心转储关闭，文件描述符上限为 64。父进程按执行
期限终止并回收超时的工作进程，并取消该程序等待的异步工具调用。工作
进程设置父进程退出信号与 ``no_new_privs``，父进程意外退出时终止计算。

.. list-table::
   :header-rows: 1

   * - 环境变量
     - 默认值
     - 含义
   * - ``AGENTSOCIETY_CODE_EXEC_TIMEOUT``
     - ``10``
     - 程序执行及工具等待的期限，秒
   * - ``AGENTSOCIETY_CODE_EXEC_MEMORY_MIB``
     - ``512``
     - 每个数值工作进程的地址空间上限，MiB
   * - ``AGENTSOCIETY_CODE_EXEC_WORKERS``
     - ``4``
     - 同一事件循环共享的数值工作进程数量上限

工作进程懒启动并复用。首次启动的期限为 10 秒；进程槽位排队与启动
时间单列于程序执行期限之外。超时、取消或协议异常导致进程退役，
后续请求重新建立工作进程。``await router.close()`` 释放所属进程资源。

工作进程按需加载 NumPy：普通数据和标量计算先使用标准库，数组传输或
NumPy 名称空间访问再加载数值库。同一工作进程继续复用已加载的 NumPy。
冷启动计量分别记录首次标量请求、随后首次 NumPy 请求及两者合计；
直接使用 NumPy 的新工作进程另行计量。首次 NumPy 导入发生在程序执行
或数组解码阶段，计入该执行请求的期限；短期限数值作业可提前预热工作进程。

环境工具保有宿主进程权限，其同步计算、文件访问和事务行为由工具实现
控制。工作进程继承操作系统用户的文件权限；生成代码可见接口由导入、
属性及数值库能力策略共同限制。执行帧、代码对象、回溯及生成器/协程
公开的 frame/code 属性在运行时拒绝访问。
异常日志可读取 ``type(error).__name__``；运行时使用内置类型描述符取得
名称字符串，绕过自定义元类 getter。其他私有属性继续由原有规则拒绝。
``asyncio`` 名称空间提供 ``sleep`` 协作式等待；任务创建、线程和 I/O
操作通过环境工具与宿主调度器管理。
Future、执行循环及其类型对象的属性访问一并受限，阻止从等待对象取得
执行循环或通过类型对象获取其方法。

数据边界与缓存
--------------

工具参数、返回值、上下文和结果使用带类型标签的 JSON 数据协议，支持
普通容器、整数键、日期时间、bytes、Decimal、Fraction、复数，以及
非对象、非结构化 dtype 的 NumPy 数组。Pydantic 响应传递字段数据，
程序通过字段属性或 ``model_dump()`` 读取；宿主模型的方法保留在宿主。
运行对象、可调用对象与未列出的数据类型返回明确的传输错误。

普通字符串键字典直接编码为 JSON 对象；包含协议保留键 ``t`` 或非字符串键
的字典使用带标签的键值对，保留原始键类型及字面内容。两种形式共用节点、
深度和标量数据上限。完整 Python 工作进程比较执行前后的上下文协议字节；
上下文未变化时只返回结果，宿主保留原始上下文对象。类型、浮点符号、
字典顺序或嵌套数据变化时返回完整上下文，并执行原有校验和回写。

单个消息上限为 8 MiB，单个数组传输上限为 4 MiB，数据节点上限为
65536、嵌套上限为 64。生成源码上限为 1 MiB；准备缓存最多保留 128 项，
单份缓存源码上限为 65536 字节。输出上限为 65536 字符。受限操作计划
最多包含 512 个 AST 节点；数据数组选择和比较的结果上限为 4 MiB。

静态验证与准备结果按源码和策略缓存；工作进程复用最多 32 份策略绑定。
每次执行创建独立上下文、结果、输出和期限。模块许可、数值库限制和
验证器变化均在相应策略边界重新核验。
受限工具计划直接进入计划执行器；数值库运行策略仅在执行完整 Python
程序时构建。

`Python resource 文档 <https://docs.python.org/3.12/library/resource.html>`_。
