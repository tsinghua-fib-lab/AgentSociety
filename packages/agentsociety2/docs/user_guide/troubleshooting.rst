常见问题
========

先区分问题发生在哪一层：平台负责启动开发环境，code-server 提供网页 IDE，AgentSociety 后端提供研究 API，模型供应商处理 LLM 请求。IDE 能打开，不代表后端和模型连接都已就绪。

code-server 显示 unhealthy
--------------------------

**原因**：新工作空间需要启动 IDE 与配套进程，平台状态更新和服务就绪可能有短暂时间差。

**处理**：等待状态变为 Running 后重新进入。持续异常时查看工作空间启动日志，再重启该工作空间；模型 API Key 不会修复 IDE 启动问题。

打开 code-server 后显示 502 错误
--------------------------------

**原因**：访问网关暂时无法连接 IDE 服务。它与插件调用后端失败属于不同链路。

**处理**：先确认平台工作空间正在运行，再检查 IDE 启动日志。若 IDE 正常、只有技能或回放失败，转而查看插件的后端状态与 AI Social Scientist 输出日志。

本地 Python 环境路径问题
------------------------

**原因**：终端使用的 Python 与扩展启动后端时使用的 Python 可能不是同一个；终端能导入 SDK，不代表扩展选择的解释器也装了 SDK。

**处理**：在已安装 SDK 的环境中执行下列命令，将输出的解释器路径填入配置向导的后端服务步骤，再重新启动后端。

.. code-block:: bash

   python -c "import sys; print(sys.executable)"
   python -c "from importlib.metadata import version; print(version('agentsociety2'))"

使用 uv 时，在项目目录把上面的 ``python`` 换成 ``uv run python``。安装与依赖要求见 :doc:`/installation`。

模型连接成功，为什么运行时仍失败？
----------------------------------

**原因**：连接测试只能验证当次请求。实际任务还可能使用 Coder 或 Embedding 角色，依赖不同模型、协议、上下文长度与供应商额度。

**处理**：按错误日志定位失败角色，核对对应模型 ID、协议和 API 配置。401/403 通常与凭据或权限有关，429 通常与额度或速率有关；应同时阅读供应商返回的错误正文。重试不能修复无效凭据。

配置项与推理控制说明见 :doc:`configuration`、:doc:`cli-gateway`；请求使用的模型以实际供应商配置为准。

实验运行失败
------------

先查看 ``run/output.log`` 中最早出现的错误，避免只根据最后一条汇总消息判断原因。

* **模块或参数错误**：核对 ``init/init_config.json`` 与所用模块的初始化参数；合法 JSON 仍可能包含错误的模块名或字段值。
* **内存不足**：先缩小智能体规模与单批任务量，再检查是否保留了过大的上下文或输入数据。减少总步数主要缩短运行与数据积累，不一定降低单步峰值内存。
* **模型请求失败**：检查失败角色、协议、额度及供应商错误；不要把服务限流误判为实验配置错误。

恢复运行前确认已有检查点；可用的恢复方式见 :doc:`/cli`。独立重跑使用新的输出目录，避免把两次实验的追加数据混在一起。

后端已启动，但回放没有数据
--------------------------

**原因**：启动后端只提供 API，不会自动执行实验。回放依赖运行过程写出的数据集及其 catalog。

**处理**：确认工作台选中的假设与实验，检查该实验的 ``run/replay/_schema.json`` 和 JSONL 分片。缺少 catalog 时先检查实验是否真正启动、是否启用了回放；有 catalog 但没有目标数据时，检查环境模块是否声明并写入了对应数据集。

SDK 快速入门生成的独立目录可用 ``ReplayReader`` 读取；插件回放按研究工作区中的假设 / 实验目录定位数据。目录约定见 :doc:`/storage`。

API 返回 403、422 或 500
------------------------

.. dropdown:: 按状态码定位问题
   :open:

   * **403**：查看响应正文。可能是 ``workspace_path`` 与后端绑定目录不一致，也可能是浏览器来源不受信任；切换项目后应重新绑定后端，不能只更换 URL 参数。
   * **422**：请求未通过参数校验。对照运行中 Swagger 的必填字段、类型及路径参数；它通常发生在业务逻辑执行前。
   * **500**：检查后端输出中的具体异常；未设置 ``WORKSPACE_PATH``、文件读取失败或运行时错误都可能导致此响应，状态码本身不能确定根因。

接口入口与只读请求示例见 :doc:`/api/http`。后端的 LLM API Key 只用于模型调用，不能替代后端访问配置。

为什么 ask 没推进时间，仍有日志和模型用量？
-------------------------------------------

``ask()`` 通过辅助器规划只读查询；只读约束指不允许调用环境写工具，不代表不调用模型或不记录日志。推进仿真时钟需要 ``step()`` 或 ``run()``；修改环境使用 ``intervene()``。具体工具取决于挂载的环境模块，见 :doc:`/interaction`。

tick=600 是要等十分钟吗？
-------------------------

不是。``tick`` 表示每步推进的模拟秒数，真实耗时取决于模型延迟、智能体规模、工具和并发调度。两步、每步 600 秒表示模拟时间前进 20 分钟，不能据此推算机器运行时间。

为什么实验结束后没有分析报告？
------------------------------

仿真执行与研究分析是两个阶段。运行结束产生原始记录；分析技能还需要读取数据、核对证据并生成图表与报告。先检查实验数据，再启动相应分析任务；报告位置与阶段说明见 :doc:`/results`。

导入别人的工作区后无法运行
--------------------------

分享包不含模型密钥。请在配置页填写自己的 API Key，核对可用模型、Python 环境和自定义模块依赖，再启动后端。路径或模型名相同，也不代表双方环境与权限相同。

为什么同一配置两次结果不同？
----------------------------

LLM 采样、上下文差异、供应商模型更新和并发执行都可能改变行为轨迹。记录模型 ID、采样参数、配置、输入数据、软件版本与重复次数，有助于判断差异来自方法还是运行条件。配置与离线检查示例见 :doc:`/examples`；复现实验应比较约定指标，不只比较逐字回答。

更多 CLI 使用方法见 :doc:`/cli`，研究技能详见 :doc:`/skills`。
